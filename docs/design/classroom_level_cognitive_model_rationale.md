# 認知モデルで生徒AIを制御する理由

作成日: 2026-07-28

## 結論

本研究で生徒AIを認知モデルによって制御する理由は、個々の生徒AIを教育するためではない。

目的は、教師が教室全体を見たときに、どのような授業構成・支援方針を選ぶべきかを検討できる教育シミュレーション環境を作ることである。

そのためには、生徒AIの反応が毎回LLM任せで揺れるのではなく、理解度、誤概念、問題難易度、個人特徴に応じて一貫して変化する必要がある。

## 研究の中心

本研究の中心は、次の問いである。

> 教師1人が複数の生徒を対象に授業を行う場面で、クラス全体の状態を踏まえた授業設計を支援・検証するために、制御可能な生徒AI集団を構成できるか。

つまり、見たい対象は「1人の生徒AIが賢くなること」ではなく、「複数の生徒AIがいる教室全体の状態」である。

## なぜLLMだけでは不十分か

LLMだけで生徒役を作ると、自然な発話は作りやすい。

しかし、教育シミュレーションとして使う場合には次の問題がある。

| 問題 | 内容 |
| --- | --- |
| 条件固定が難しい | 同じ理解度・同じ問題でも、LLMの出力が揺れる |
| 正誤の理由が不明確 | なぜ正答したか、なぜ誤答したかを説明しにくい |
| クラス分布を設計しにくい | 低理解層・中間層・高理解層を意図的に配置しにくい |
| 授業方針との対応が見えにくい | 教師AIが何を見て授業構成を変えたのか検証しにくい |
| 再現性が弱い | 同じ条件で比較実験を繰り返しにくい |

教室全体を見る研究では、発話の自然さだけでなく、クラス内にどのような理解度分布・誤概念分布・質問傾向分布があるかを制御できることが重要になる。

## 認知モデルを入れる意味

認知モデルは、生徒AIの正答・誤答やつまずきを決める制御層である。

現在の設計では、次の要素から正答確率を決める。

- スキル別理解度
- 単元全体の理解度
- 問題難易度
- guess
- slip
- 誤概念ペナルティ
- 自己効力感・意欲による補正

これにより、次のような教室状態を意図的に作れる。

| 作りたい教室状態 | 認知モデルで操作するもの |
| --- | --- |
| 全体的に理解が低いクラス | 多くの生徒の総合理解度を低くする |
| 一部だけ高理解のクラス | 高理解生徒と低理解生徒を混在させる |
| 移項でつまずくクラス | can_transpose_terms を低くする |
| 係数除算で誤る生徒が多いクラス | can_divide_by_coefficient と関連誤概念を操作する |
| 質問しにくいクラス | question_tendency を低めに設定する |
| 自信が低い生徒が多いクラス | self_efficacy を低めに設定する |

つまり、認知モデルは「生徒AIを賢くするため」ではなく、「教室全体の条件を設計するため」に使う。

## 教室全体を見るために必要なこと

教師が実際の授業で見ているのは、1人の完全な内部状態ではない。

教師が見られるのは、たとえば次のような観察可能な情報である。

- 生徒の発話
- 正答・誤答
- 途中式
- 質問の有無
- 迷い方
- 反応の短さ
- クラス全体のつまずき傾向

本研究では、生徒AIの真の内部状態を教師AIに直接渡すのではなく、まず生徒AIに発話や正誤反応を出させる。

その後、伝達AIが観察可能な情報を要約し、講義設計AIがクラス全体に対する授業方針を考える。

```text
生徒AI集団
  -> 発話・正誤・反応
伝達AI
  -> 観察可能情報からクラス状態を要約
講義設計AI
  -> クラス全体に合う授業構成を提案
教師AI
  -> 全体説明・個別支援の発話を作る
```

この流れを検証するには、生徒AI集団の状態を外部から制御できる必要がある。

## 1人生徒AIと複数生徒AIの違い

1人の生徒AIでは、主に次を確認する。

- 理解度を上げると正答率が上がるか
- 誤概念があると関連問題で誤りやすくなるか
- 個人特徴が発話に出るか

しかし、教室全体を見る場合には、関心が変わる。

| 観点 | 1人生徒AI | 複数生徒AI |
| --- | --- | --- |
| 見たいもの | その生徒が解けるか | クラス全体にどんな分布があるか |
| 主な出力 | 1人分の正答確率・発話 | クラス平均、低理解層、共通弱点、個別支援対象 |
| 教師AIへの意味 | その生徒への個別対応 | 全体説明、演習設計、個別支援の配分 |
| 評価したいこと | 生徒AI単体の制御性 | クラス状態に応じて授業設計が変わるか |

したがって、生徒AIの設計は、最終的には複数生徒クラスのシミュレーションに接続される。

## 発表での説明文

発表では、次のように説明するとよい。

> 本研究で生徒AIを認知モデルで制御する理由は、1人の生徒AIを教育することではありません。目的は、教師1人が複数生徒を見ながら授業を行う教室場面をシミュレーションすることです。そのためには、低理解の生徒、高理解の生徒、特定の誤概念を持つ生徒、質問しやすい生徒、質問しにくい生徒を、意図的に同じクラス内へ配置できる必要があります。認知モデルを使うことで、生徒AIの正答・誤答・つまずき方を外部状態から制御でき、クラス全体の分布を設計できます。これにより、教師AIや講義設計AIが、観察されたクラス状態に応じて授業方針を変えられるかを検証できます。

## スライド用の短い表現

### 一文版

生徒AIを認知モデルで制御するのは、個々の生徒を教育するためではなく、教師AIが教室全体を見て授業方針を変えられるかを検証するためである。

### 箇条書き版

- 目的は生徒AIの教育ではなく、教室全体の授業シミュレーション
- 複数生徒の理解度・誤概念・個人特徴を分布として設計する
- 認知モデルにより、正答率・誤答傾向・つまずき方を制御する
- 教師AIは観察可能な反応からクラス状態を把握する
- 最終的に、クラス状態に応じた授業構成の提案を検証する

## 主張できることと主張しないこと

### 主張できること

- 生徒AIの内部状態を外部から制御できる
- 理解度や誤概念に応じた正答確率を生成できる
- 複数生徒の状態分布を設計できる
- クラス全体の弱点や支援対象を可視化できる
- 教師AIの授業設計を検証するための条件を作れる

### まだ主張しないこと

- 実際の生徒の認知過程を忠実に再現している
- 人間生徒と区別できない発話を生成できる
- 30人クラスの分布が実在クラスを代表している
- 教師AIの授業が実際に学習効果を高める
- BKT/IRTのパラメータを実データから推定済みである

## 今後の検証

今後は、次の順に検証する。

1. 認知モデルの内部整合性
   - 理解度、難易度、誤概念、弱点スキルを変えたときに期待通り結果が変わるか

2. 発話妥当性
   - 個人特徴が発話量、質問、不安表現などに反映されるか

3. クラス要約の妥当性
   - 伝達AIが複数生徒の観察情報からクラス状態を要約できるか

4. 授業設計への接続
   - 講義設計AIがクラス状態に応じて授業構成を変えられるか

5. 外的妥当性
   - 実際の生徒データや人間評価と比較できるか
