# 2026-08-07 作業メモ

## 授業シミュレーションへの認知モデル組み込み

教育シミュレーション環境で、生徒AIの正誤制御に `src/cognitive_model.py` の認知モデルを使うように整理した。

これまでの設計方針では、LLMに生徒の正答・誤答を自由に決めさせず、認知モデルが正誤方針を決め、LLMは発話生成を担当することにしていた。今回、授業時間経過シミュレーション側でもこの方針に合わせ、確認問題など採点対象フェーズでは `bkt_irt` 認知モデルから assessment directive を作り、生徒AIへ渡す流れにした。

## 現在の流れ

1. 授業設計AIが教師beliefとクラス状態から授業構成を作る
2. 授業中の確認問題フェーズで認知モデルが正答確率・正誤方針を決める
3. 生徒AIは認知モデルの方針と個人特徴に基づいて発話する
4. 伝達AIは観察可能な生徒発話・正誤・反応時間などからクラス状態を要約する
5. 教師beliefを更新し、次サイクルの授業設計に反映する

## 実装上の変更

- `LessonSessionRunner` に認知モデルを追加
- 標準の認知モデルを `bkt_irt` に設定
- 採点対象フェーズでは認知モデルの assessment directive を生徒AIへ渡す
- シミュレーション条件に `cognitive_model` を記録
- CLIとColab Notebookから認知モデルを明示的に指定できるようにした

## 確認結果

- `py -m pytest`: 93 passed
- `scripts/run_simulation_timeline.py --class-size 5 --cycles 3 --cognitive-model bkt_irt` が成功
- 出力結果に `cognitive_model: bkt_irt` が記録されることを確認

## 研究上の意味

この変更により、生徒AIは単なるランダム応答やLLM任せの発話ではなく、認知モデルによって制御された学習者代理として授業シミュレーションに入る。これにより、教師AI・伝達AI・授業設計AIの評価を、制御可能なクラス条件のもとで行いやすくなる。

## 伝達AIのpriority過剰判定を修正

シミュレーション結果で、5人クラス全員が `priority_students` に入る問題を修正した。

原因は、伝達AIが「質問していない」「返答が短い」だけでも低質問傾向・低モチベーションとして扱い、さらにpriority候補へ入れていたためである。授業の導入や全体説明では、生徒が質問しないこと自体は強いリスク証拠ではないため、観察フェーズに応じた補正を追加した。

変更点:

- 非採点フェーズでは、質問がないだけで `question_tendency=low` としない
- 非採点フェーズでは、短い相づちだけで `motivation=low` としない
- priority判定は、誤答・無反応・低自己効力感・高不安などが一定以上重なった場合に絞る
- 5人クラスで2人程度の要支援は通常範囲とし、半数超の場合にissue候補とする

確認結果:

- `py -m pytest`: 94 passed
- `simulation_timeline_for_codex.txt` では `priority_count` が全員5人から2人に改善
- 導入・全体説明フェーズの `low_question` と `low_motivation` の過剰推定が改善

## 小規模LLM実行セルを追加

教育シミュレーションにLLMを入れて確認できるよう、`simulation_timeline_experiment.ipynb` に小規模LLM実行セルを追加した。

通常の3サイクル実験は軽量なmockのまま残し、LLM実験は3人・1サイクルで実行する構成にした。これにより、Colab上で初回モデルロードが重い場合でも、生徒発話LLMと伝達AI LLMの動作を小さく確認できる。

追加内容:

- `USE_LLM_STUDENT_SMALL = True`
- `USE_LLM_COMMUNICATION_SMALL = True`
- `LLM_CLASS_SIZE = 3`
- `LLM_CYCLES = 1`
- 出力ファイル `simulation_timeline_llm_for_codex.txt`

また、Colabでgit更新後に古い `src` モジュールが残る問題を避けるため、セットアップセルで `src` 系importキャッシュを削除する処理を追加した。実験結果には `git_commit` も記録し、どのコミットで生成された結果か確認できるようにした。

## 正誤判定を認知モデル由来に統一

LLM生徒発話を入れたとき、発話形式の揺れにより、正解しているはずの反応が採点器で不正解扱いになる問題が見つかった。

教育シミュレーション本体では、生徒AIの正誤は認知モデルが制御する方針であるため、授業中の観察結果 `is_correct` は認知モデルの `target_correct` を使う形に変更した。一方で、発話から採点器が読み取った結果は `observed_grade` として別に保存する。

追加した指標:

- `accuracy`: 認知モデル由来の正答率
- `observed_accuracy`: 発話を採点器で読んだ場合の正答率
- `grading_agreement`: 認知モデル正誤と採点器正誤の一致率
- `grading_mismatch_count`: 両者が一致しなかった件数

これにより、授業シミュレーションの正答率は認知モデルに基づいて安定させつつ、LLM発話が採点器にとって読み取りやすいかどうかも別指標として確認できる。
